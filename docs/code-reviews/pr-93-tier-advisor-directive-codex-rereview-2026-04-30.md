## Blockers

1. The exit-code contract is still not unified all the way through the directive. The new exit-code table says hard errors are exit `4`, but the edge-case test for missing inputs still says "`if both missing, error and exit 3`." Exit `3` is already reserved for `tier:unknown`, so this remains a contradictory contract for implementers and tests. References: [proxy-tier-advisor.md](/home/manager/git_repos/claude-code-cache-fix/docs/directives/proxy-tier-advisor.md:231), [proxy-tier-advisor.md](/home/manager/git_repos/claude-code-cache-fix/docs/directives/proxy-tier-advisor.md:232), [proxy-tier-advisor.md](/home/manager/git_repos/claude-code-cache-fix/docs/directives/proxy-tier-advisor.md:336).

2. The old per-run downgrade counter still survives in the test plan and JSON schema, which reopens the "weeks vs runs" ambiguity the new weekly-state text was supposed to remove. The directive now says the downgrade gate is driven by `state.weeks`, but the documented JSON output still carries `weeks_under_downgrade_threshold`, and tests 18-21 still describe an empty `history` plus increment/reset behavior for `weeks_under_downgrade_threshold`. As written, an implementation could satisfy those tests by keeping the stale run counter alongside the new weekly array, which is not the contract the fix claims to establish. References: [proxy-tier-advisor.md](/home/manager/git_repos/claude-code-cache-fix/docs/directives/proxy-tier-advisor.md:152), [proxy-tier-advisor.md](/home/manager/git_repos/claude-code-cache-fix/docs/directives/proxy-tier-advisor.md:160), [proxy-tier-advisor.md](/home/manager/git_repos/claude-code-cache-fix/docs/directives/proxy-tier-advisor.md:213), [proxy-tier-advisor.md](/home/manager/git_repos/claude-code-cache-fix/docs/directives/proxy-tier-advisor.md:316), [proxy-tier-advisor.md](/home/manager/git_repos/claude-code-cache-fix/docs/directives/proxy-tier-advisor.md:318), [proxy-tier-advisor.md](/home/manager/git_repos/claude-code-cache-fix/docs/directives/proxy-tier-advisor.md:319).

## What Needs Attention

- The scope sentence at the top still says "Exit-code semantics depend on mode" even though the rewritten contract below is explicitly mode-invariant. The later section is clear enough to infer the intended behavior, so I am not treating this as a separate blocker, but the wording should be tightened when the blocking inconsistencies above are fixed ([proxy-tier-advisor.md](/home/manager/git_repos/claude-code-cache-fix/docs/directives/proxy-tier-advisor.md:46), [proxy-tier-advisor.md](/home/manager/git_repos/claude-code-cache-fix/docs/directives/proxy-tier-advisor.md:224)).

## Recommendations

- Fix the remaining exit-code contradiction by making all hard-error cases use exit `4` everywhere, including test 31 and any surrounding prose.
- Remove or redefine the stale `weeks_under_downgrade_threshold` / `history` references so the downgrade contract is unambiguously calendar-week based end-to-end. If a derived counter is still wanted in `--json`, define it explicitly as computed from `state.weeks`, not persisted or mutated per run.
- Update tests 18-21 to assert the new weekly-state behavior instead of the old run-counter behavior. Right now tests 35-38 add the new model, but 18-21 still preserve the old one.

## Bottom Line

Revise once more before directive approval. Commit `3ca1544` fixes the main logic sections for burn-rate source selection, unknown-plan handling, and calendar-week tracking, and it preserves the previously-correct CLI/statusline shape and upgrade/downgrade asymmetry. But the directive still contains two contract-level leftovers: one exit-code contradiction and one stale per-run downgrade model in the documented schema/test plan. Those should be cleaned up before this moves to implementation.
