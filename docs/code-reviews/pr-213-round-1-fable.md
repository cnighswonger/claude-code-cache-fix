# PR #213 — image-retry circuit breaker directive — round 1 (Fable)

Reviewed at HEAD `bdf93ae` (directive stage, no implementation yet). Verified against `proxy/pipeline.mjs`, `proxy/server.mjs`, `proxy/stream.mjs`, `proxy/extensions/{bootstrap-defense,image-strip,cache-telemetry,usage-log,prefix-diff}.mjs`, and `proxy/extensions.json` at current `main`.

## What Is Correct

- The problem framing is right and well-sourced. CC#66815's cost mechanism (each retry rebuilds the full cache_creation surface) is accurately described, and the proxy is the correct layer for the fix — it sees both the failure response and the identical retry.
- Hashing decoded image bytes rather than the base64 string is the right call; re-encoding variance is a real false-negative source.
- The four-part conjunctive detection (error class AND hash match AND time window AND session match) with fail-open on any miss is the right safety posture, as is the `dry-run` mode for production validation.
- The activation model (always-loaded, env-var-gated, default-off pending a validation cycle) matches the established `prefix-diff` pattern (`proxy/extensions/prefix-diff.mjs:30`, `enabled: true` + `CACHE_FIX_PREFIXDIFF` gate).
- In-memory-only state with documented restart-resets-breaker semantics is appropriate for a 30s cool-off window.
- Per-session + per-image-hash keying is the correct isolation granularity, and the test plan covers both isolation axes.
- The replay-fixture integration test (1 upstream call, 18 short-circuits) is exactly the right acceptance shape for the headline claim.

## Blockers

**B1. The hook surface named in the directive does not exist.** The pipeline (`proxy/pipeline.mjs:85-141`) exposes exactly four hooks: `onRequest`, `onResponseStart`, `onStreamEvent`, `onResponse`. The directive's Implementation Choice section runs the breaker in `onRequestStart` and records failures in `onResponseEnd` — neither exists. Additionally, the short-circuit mechanism is mis-described: `bootstrap-defense` does not "set `ctx.response` directly"; it returns `{skip: true, status, headers, body}` from `onRequest` (`bootstrap-defense.mjs:176-182`), which `preForward` in `server.mjs:88-95` converts into a direct client write. The directive cites bootstrap-defense as its precedent while describing a mechanism that isn't the one bootstrap-defense uses. The recording side must also be specific: `runOnResponse` only fires on the **non-streaming** branch of `handleMessages` (`server.mjs:162-187`) — pre-stream API errors (HTTP 4xx JSON, which is how "image could not be processed" arrives) will reach `onResponse`, but the directive needs to say so and address whether mid-stream `error` SSE events (via `onStreamEvent`) are in or out of scope.

**B2. `proxy/lib/anthropic-error-classes.mjs` does not exist and is presented as existing.** Detection condition 1 states "the exact error-class taxonomy lives in `proxy/lib/anthropic-error-classes.mjs`; this extension reuses it rather than introducing its own." There is no `proxy/lib/` directory in the tree, no `anthropic-error-classes.mjs` anywhere in the repo, and the file is absent from the directive's own "Files created" list — yet the reviewer checklist requires the predicate to reference it. Either declare it as a new file (with its contents specified: which error types/messages constitute the "image could not be processed" family) or inline the predicate. As written, the predicate's contract is unverifiable. Note also that existing shared helpers live flat in `proxy/` (`helpers.mjs`, `image-dimensions.mjs`, `image-resize.mjs`) — introducing a `proxy/lib/` directory is a convention change that should be explicitly declared, affecting `image-hash.mjs` too.

**B3. The synthesized response ignores `stream: true`.** CC sends Messages requests with `stream: true`; the upstream success envelope is an SSE event sequence, not a JSON document. The `{skip:true}` path writes a single JSON body (`server.mjs:92-94`) — fine for bootstrap-defense because the bootstrap route is non-SSE, but on the messages route the harness's SDK expects `text/event-stream` when it asked for a stream. A non-SSE 200 JSON body to a streaming request has undefined harness behavior and may itself be treated as a transport error and retried — which would defeat the breaker entirely. The directive must specify either (a) synthesizing a minimal valid SSE sequence (`message_start` → `content_block_start` → `content_block_delta` → `content_block_stop` → `message_delta` → `message_stop`) when the request carries `stream: true`, or (b) evidence that the harness accepts a non-SSE 200 for a streamed request. This is the single highest-risk gap: if the synthesized response doesn't convince the harness, the whole feature fails its acceptance test. The sim-validation requirement (label `needs-sim-validation`) should be mandatory for this PR.

**B4. The `usage: 0` meter-pipeline claim is false.** The directive calls the zeroed usage block "load-bearing: it signals to the meter pipeline that no upstream cost was incurred." Verified against the consumers: `usage-log` assembles records exclusively from `message_start`/`message_delta` SSE events in `onStreamEvent` (`usage-log.mjs:273-319`), and `cache-telemetry` likewise (`cache-telemetry.mjs:190-272`). A short-circuited request returns from `preForward` with `{handled: true}` before any upstream call — no stream events, no `onResponseStart`, nothing reaches either consumer. The synthesized response is therefore invisible to the meter pipeline (which is arguably correct — no cost was incurred), and neither consumer treats `usage: 0` distinctively in any case. The zeroed block is harness-facing cosmetics. Fix the claim, and state explicitly that short-circuited requests produce no `usage.jsonl` row — the JSONL event log is the only observability surface for breaker fires.

## What Needs Attention

1. **Order-370 rationale is internally inconsistent.** The directive places the breaker at 370 "before any potential mutation" of image content blocks — but `image-strip` runs at order **150** and mutates images (strip, resize via Pass 3) well before 370. At 370 the breaker hashes post-mutation content. That is probably the *correct* behavior (hash what actually goes upstream, consistently on both the failing request and the retry), but the stated rationale is wrong. Also "request-shape normalization at 350" is actually `microcompact-stability`; name it precisely.
2. **Multi-image false positive.** Detection condition 2 fires if *any* image hash matches the previous failed request. A user whose request had images A (bad) + B (good), and who replaces A and retries with A′ + B, still matches on B's hash and gets short-circuited — blocking a legitimately corrected retry. The "Out of scope" note asserts per-image-hash partial short-circuits are "the correct behavior," but as specified the breaker is per-*request*, keyed on any-hash-match. Either record only hashes plausibly implicated in the failure, or require the *full* image-hash set to match, or explicitly accept this false positive with the 30s TTL as the mitigation — but decide it in the directive.
3. **Session-id fallback is ambiguous.** "Fallback to the proxy's `sid`" — `sid` in this codebase means usage-log's boot-sticky 8-char id (`usage-log.mjs:62`), which is module-private and not a per-request concept. The established resolver is `resolveSessionId` in `cache-telemetry.mjs:64-72` (exported precisely for sibling-extension reuse; checks three header names, not just `x-claude-code-session-id`). Reference that, and define the no-session bucket explicitly (e.g. key `"unknown"`, matching `sessionFilename`'s convention).
4. **State cleanup discipline is unspecified.** The per-(session, hash) map grows monotonically on a long-running proxy. With a 30s TTL the live set is small, but dead entries need eviction — specify lazy expiry on lookup plus a throttled sweep (precedent: `sweepStaleSessions`, `cache-telemetry.mjs:132-156`). Cheap to specify now, a leak report later otherwise.
5. **Transcript pollution by the synthetic assistant turn.** The synthesized message becomes a real assistant turn in conversation history — the `[cache-fix-proxy] …` text is now context the model sees on every subsequent request in that session, and the harness may act on it as if the model said it. Probably acceptable (it's one short block, and it does instruct the right remediation), but the directive should acknowledge the trade-off and keep the text minimal/stable.
6. **Recording-side plumbing is glossed over.** At `onResponse` time, `ctx.body` is the *response*; the failing request's image hashes must have been stashed on `ctx.meta` during `onRequest` (the same `meta` object flows through the pipeline — see `cache-telemetry.mjs` onRequest stash pattern). One sentence in the directive makes this implementable without guesswork.
7. **Test plan gaps:** (a) no test for `stream: true` short-circuit behavior (per B3 — this is the critical path); (b) no replaced-bad-image multi-image case (per attention item 2); (c) no sessionless-request case; (d) no live-CC sim validation despite the repo having a `needs-sim-validation` label and a Proxy Test Agent for exactly this; (e) no test that the error-class predicate rejects near-miss errors (e.g. `overloaded_error`, rate-limit 429s) — false-positive protection deserves a test, not just true-positive replay.

## Bloat / Non-Functional

- The 150–250 LOC budget "including state machine + content-hash helpers + tests" is not credible: five test files plus extension plus hash helper plus (per B3) SSE synthesis will comfortably exceed it. Either re-state the budget as extension-code-only or raise it; an inaccurate NFR invites either corner-cutting or budget-theater at implementation review.
- JSONL event log: pin the PII discipline now, the way `bootstrap-defense` does (`bootstrap-defense.mjs:69-76`) — hashes, session id, timestamps, remaining-TTL only; never image bytes, never request bodies, never auth headers. Also specify rotation (precedent: `rotateIfNeeded`, 5MB single-tier) — an unbounded JSONL in `~/.claude/` is a slow-burn disk leak.
- `IMAGE_RETRY_COOLOFF_MS` is named as a constant but not declared as an env-var; the Scope section lists only `CACHE_FIX_IMAGE_RETRY_BREAKER`. If the TTL is operator-tunable, name the env var (`CACHE_FIX_IMAGE_RETRY_COOLOFF_MS`); if not, say it's a code constant.

## Recommendations

1. Rewrite Implementation Choice against the real hook surface: decide in `onRequest` returning `{skip: true, status: 200, headers, body}`; record failures in `onResponse` (pre-stream HTTP-error path), with the request's image hashes stashed on `ctx.meta` at `onRequest` time; state explicitly whether mid-stream SSE `error` events are handled (recommend: out of scope v4.2.0, documented).
2. Resolve the error-class taxonomy: add `anthropic-error-classes.mjs` to "Files created" with its predicate contract spelled out (status codes + `error.type`/message patterns it matches), or inline a documented predicate and drop the shared-lib framing. Decide flat `proxy/` vs new `proxy/lib/` explicitly.
3. Specify SSE synthesis for `stream: true` requests (or harness evidence that JSON-200 suffices), and make sim validation a merge gate for this PR.
4. Correct the `usage: 0` paragraph: the skip path bypasses the meter pipeline entirely; the JSONL event log is the sole observability surface for breaker fires.
5. Decide the multi-image matching rule (any-hash vs full-set vs accept-and-document) and add the replaced-image test either way.
6. Swap the session-id language to `resolveSessionId` reuse and add map-eviction discipline.

## Bottom Line

The problem is real, the layer is right, and the detection/safety posture (conjunctive conditions, fail-open, dry-run, env-gate) is well designed. But the directive's load-bearing mechanics don't survive contact with the codebase: both named hooks don't exist, the cited error-class module doesn't exist, the synthesized response ignores that the harness streams, and the meter-pipeline claim is verifiably false. These are all fixable in one revision pass — none invalidate the design, but all four would surface as rework at implementation review if approved now. Fix B1–B4 (and decide attention items 2–3), and this is approvable in round 2.
