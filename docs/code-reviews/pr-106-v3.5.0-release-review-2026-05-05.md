# Review: v3.5.0 release readiness

Date: 2026-05-05
Reviewed: PR #106 (`release: v3.5.0`, commit `864c2e9`)
Label applied: changes-requested

## What Is Correct

- `package.json` is bumped to `3.5.0`.
- `package-lock.json` is not tracked in this repo, so there is no tracked lockfile version drift to correct.
- The new `## [3.5.0] - 2026-05-05` section is present and the breaking path-change call-out is prominent at the top of the release notes.
- Comparing `HEAD^:CHANGELOG.md` to `HEAD:CHANGELOG.md`, the unreleased entries were carried into the `3.5.0` section with no feature/fix bullets dropped. The release commit also corrected stale metadata in that text (`#104` → `#105`, `698 → 732 (+34)` → `698 → 733 (+35)`).
- `npm test` passes at 733/733, matching the release claim.
- `package.json`'s `files` array is unchanged from `v3.4.0`.
- Based on the already-approved PR #105 content and the release diff here, this is a filesystem/statusline-path break for custom consumers, not an HTTP proxy API break and not an extension interface contract break. Minor bump remains consistent with `docs/release-workflow.md`.

## Blockers

- `npm pack` would currently ship a leaked local-only config change in `proxy/extensions.json`. The committed blob at `HEAD:proxy/extensions.json` is the expected default config, but the working tree is auto-mutated on checkout by the cache-fix hook:
  - checkout output: `[cache-fix hook] re-applied usage-log local mod (order 650) to extensions.json`
  - working tree diff adds:
    - `"usage-log": { "enabled": true, "order": 650 }`
  - extracting the generated tarball confirms that `package/proxy/extensions.json` contains that leaked `usage-log` entry.
  This is exactly the class of release leak called out in the release request, so the release is not ready to ship until packaging is guaranteed to use the default config.

## What Needs Attention

- `docs/release-workflow.md` says pre-flight should have no uncommitted local changes. On this branch, checkout immediately dirties the worktree (`proxy/extensions.json`) and there is also an untracked local `package-lock.json`. The tracked release commit is still clean, but the packaging path is not robust against local state.
- The release mechanics otherwise look correct, but future release checks should treat "packed tarball content" as the source of truth, not just the tracked blob or `git diff`.

## Recommendations

- Fix the packaging path before shipping `v3.5.0`. At minimum, ensure `npm pack`/`npm publish` runs from a clean tree whose `proxy/extensions.json` matches `HEAD`, or make the packaging flow explicitly restore the default config before pack/publish.
- Re-run `npm pack` after the fix and verify the extracted `package/proxy/extensions.json` has no `usage-log` entry.
- Once that blocker is fixed, this PR is otherwise ready for approval without re-reviewing PR #105's implementation logic.

## Bottom Line

Revise before release. The semver bump, changelog call-out, test count, and file list all check out, but the actual packed artifact currently leaks a local-only `usage-log` default into `proxy/extensions.json`. That is a release-blocking packaging failure for `v3.5.0`.
