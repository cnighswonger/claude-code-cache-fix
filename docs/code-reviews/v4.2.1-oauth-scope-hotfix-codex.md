## What Is Correct

The functional fix is correct. `runOnce()` re-reads the credential file inside the OAuth lock, takes `oauth2.scopes` from that locked read, passes it to `postRefresh()`, and `postRefresh()` serializes `scope(credScopes)` into the refresh POST payload. That preserves the currently granted credential scope set instead of hardcoding the v4.2.0 subset.

The resolution order is also correct: `CACHE_FIX_OAUTH_SCOPE` remains an explicit operator override, valid credential-file scopes are filtered/deduped/space-joined, and `SCOPE_FALLBACK` is reached only when the credential scopes are missing or collapse to no valid string entries.

The threat-model discipline is preserved. The new scope string is used only in the token endpoint request body; it is not added to `emitOAuthEvent()` records. The success event still carries only status, expiry, and elapsed time. Scope identifiers are authorization labels, not token material, but keeping them out of the event stream is still the right minimal-observability posture.

The regression coverage exercises the actual bug. The full-scope and `user:sessions:claude_code` tests capture the mock server's POST body and assert on the outbound `scope` field, rather than only checking the persisted credential. The fallback test deletes the credential `scopes` field and confirms a non-empty fallback scope is sent. Existing successful-refresh behavior still passes and still verifies rotated token persistence, preserved fields, and token-free events.

Release metadata is otherwise in shape: `package.json` is bumped from 4.2.0 to 4.2.1, the CHANGELOG entry accurately describes a bugfix-only hotfix, no new dependency was added, and the PR diff is limited to `CHANGELOG.md`, `package.json`, `proxy/oauth/refresher.mjs`, and `test/oauth-refresher.test.mjs`. The local `proxy/extensions.json` modification is not part of the PR diff.
